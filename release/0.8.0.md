# 0.8.0 — Observability for agents + multi-tenancy foundation

> Format: Keep a Changelog · SemVer 0.7.5 → 0.8.0 — additive + one
> additive behaviour change to the Traces filter chip semantics. New
> public API surfaces (`?group_by=trace`, `/traces/by-trace/{id}`,
> richer `/auth/me`). Five additive DB migrations (all nullable). One
> new realm-export shape (worker client + tenant groups + 6 demo
> users). No destructive migrations.

Phases A + B + C of the multi-tenancy/observability initiative ship
together as a single release. They build on each other: Phase B's trace
nesting depends on Phase A's filter UX fix to be intelligible; Phase C
multi-tenancy will need the trace-tree view from Phase B to attribute
cross-tenant activity. The three were specced separately
(`docs/specs/2026-06-29-*.md`) and developed phase-by-phase with TDD;
this release combines the diff into one shippable cut.

## Added

### Phase A — Traces filter + Agents Run reliability

- **Structured validation errors on `POST /api/v1/agents/{name}/run`.**
  `_validate_payload` now raises HTTP 422 with `detail = {"agent":
  <name>, "missing_fields": [...], "hint": "..."}` instead of a
  free-form HTTP 400 string. The Agents page renders this as an inline
  banner so users see exactly which fields they need to supply.
  Pydantic `ValidationError` is parsed for both missing-required and
  bad-type errors.

### Phase B — Agent trace nesting

- **`hermes_traces` carries trace ancestry.** Five additive columns:
  `kind` (defaults to `"skill"`), `trace_id`, `parent_span_id`,
  `span_id`, `agent_run_id`. Indexed on `trace_id` and
  `agent_run_id`. Existing rows backfill to `kind="skill"` with NULL
  trace fields — they continue to render as flat, root traces.
- **`apps/api/services/tracing.py:trace_span`.** A small
  `contextvars`-backed context manager that records a row on enter,
  updates it on close, and pushes `(trace_id, span_id)` onto a stack so
  nested calls inherit the trace. Used by:
  - `packages/agents/runner.py:stream_agent` wraps each agent run with
    `trace_span(kind="agent", agent_run_id=...)`. A
    `contextvars.copy_context()` hop is used when handing the LangGraph
    state machine to `loop.run_in_executor`, so child skill calls
    running on the threadpool inherit the agent's trace.
  - `packages/ratchet/hermes_bridge.py:_record_trace` reads the active
    span stack on every Hermes skill call and stamps the child trace
    row with the agent's `trace_id` + `parent_span_id` whenever an
    agent context is active. Legacy callers (no active span) still
    produce root rows — backwards compatible.
- **`GET /api/v1/hermes/traces?group_by=trace`.** Returns a list of
  `TraceTreeRow` (root + `children`) instead of the flat shape; orders
  trees newest-first. `kind` and `agent_run_id` query params let the
  Traces tab filter to agents only or pull all spans of one agent
  invocation.
- **`GET /api/v1/hermes/traces/by-trace/{trace_id}`.** Returns the full
  tree for one trace; 404 when unknown.
- **Traces tab tree view.** `apps/web/src/pages/Traces.tsx` gains a
  Tree | Flat toolbar toggle (default Tree). In Tree mode, each agent
  span renders as an expandable header with its child skill spans
  nested + indented + badge-tagged. Expand state is per-trace in a
  `Set<string>`. SSE `complete` event from `POST /agents/{name}/run`
  now carries `agent_run_id` + `trace_id` so the frontend can jump
  straight from the Agents page to the relevant trace.

### Phase C — Multi-tenancy foundation

- **`apps/api/services/identity.py`** — canonical `Identity` dataclass
  derived from the existing JWT-backed `User`. Maps Keycloak `groups`
  → `tenant_id` (first non-empty path segment), picks the
  highest-precedence realm role per `policies/role_matrix.rego`, and
  exposes `is_admin` / `is_worker` flags. `current_identity` is a
  FastAPI dependency that surfaces the resolved record from
  `request.state.user`. 401 when unauthenticated; 403 when
  authenticated but with no tenant group.
- **`apps/api/services/scoping.py:scope_query(stmt, identity, Model)`.**
  Adds tenant + owner WHERE clauses uniformly: admin sees all rows in
  their tenant, non-admin sees only their own, workers see nothing
  (refuses to enumerate; they consume the claim queue instead). Hard
  errors if the model is missing the migration columns — a forgotten
  `scope_query` in a new router can't become a silent cross-tenant
  leak.
- **`tenant_id` / `user_id` / `role` columns on five tables.** Run,
  TrainingSession, Export, Metric, AutoFixAttempt. All nullable so
  existing rows preserve as legacy NULL; `scope_query` refuses to
  surface legacy rows until an admin claims them.
- **`packages/common/auth.py:WorkerToken`** — thread-safe Keycloak
  `client_credentials` token fetcher. Caches the JWT until `exp -
  leeway`; auto-refreshes on next `bearer()` call. Used by
  `packages._api_client.service_headers()`, which now prefers
  `Authorization: Bearer <worker JWT>` when
  `SLM_FORGE_WORKER_CLIENT_SECRET` is set and falls back to the legacy
  `X-Service-Token` otherwise.
- **`AuthMiddleware` promotes worker JWTs.** When a token's `azp`
  (authorized party) claim equals `SLM_FORGE_WORKER_CLIENT_ID`, the
  middleware adds `role=worker` + `groups=["/tenants/system"]` to the
  derived `User` so the rest of the stack treats the worker as a
  proper tenant-identified actor. Keeps the realm-export
  self-contained — no manual role assignment to the service account.
- **OPA tenant isolation policy.** New `policies/tenant_isolation.rego`
  exposes `same_tenant`, `same_owner`, `admin_in_tenant`,
  `worker_claim_match`, and a composite `tenant_allow`. The top-level
  `slm_forge.allow` now requires `tenant_allow` in addition to the
  role-matrix check. Backwards compatible: when `input.context` lacks
  tenant/owner fields (e.g. settings endpoints) the helpers return
  `true`, so existing endpoints keep their matrix-only semantics. Plus
  two new matrix entries: `viewer` (read-only baseline) and `worker`
  (narrow scope: `claim_run`, `update_run`, `upload_artifact`,
  `read_dataset`).
- **Richer `/api/v1/auth/me`.** Returns `MeResponse` with
  `tenant_id` / `primary_role` / `is_admin` / `is_worker` alongside
  the existing User shape. Frontend `AppUser` extended to match;
  `oidc-client-ts` callers automatically pick up the new fields.
- **`TenantPill` in the top nav.** Reads `useAuth().user.tenant_id`
  and `primary_role`, renders an emerald-and-zinc chip next to the
  PlatformBadge. Falls back to an amber "⚠ no tenant" warning chip
  when the signed-in user has no Keycloak group — operators see the
  configuration gap immediately instead of debugging blank pages.
- **Keycloak realm seed.** `keycloak/realm-export.json` extended with:
  - 2 new roles: `viewer` (read-only baseline), `worker` (service
    account scope).
  - 4 tenant groups under `/tenants/`: `local` (default), `acme`,
    `globex`, `system` (workers).
  - 6 demo users: `alice@acme` (admin / `alice1234`), `bob@acme`
    (data_engineer / `bob12345`), `carol@globex` (admin /
    `carol123`), `dave@globex` (data_engineer / `dave1234`),
    `viewer@acme` (viewer / `viewer12`), `viewer@globex` (viewer /
    `viewer34`).
  - 1 confidential client `slm-forge-worker` with
    `serviceAccountsEnabled=true`, dev secret
    `slm-forge-worker-dev-secret`, 30-min access-token lifespan.
- **`make auth-token EMAIL=<demo user>`** — extended to mint JWTs for
  any of the 6 new demo users by mapping their default passwords.
- **`make auth-worker-token`** — mints a worker JWT via
  `client_credentials` grant for curl/Postman testing.

## Changed

- **Traces filter chip is now correct.** `activeFilterCount` used to
  read `(skillFilter.size > 0 ? 1 : 0)` so selecting 5 skills + a
  status filter showed "2 filters active". The chip now sums
  `skillFilter.size + (statusFilter ? 1 : 0) + …`, and the label was
  split: the chip reads `"N filter(s) active"` while the right pane
  reads `"N matching trace(s)"`.
- **Auth-disable mode is now deprecated.** `get_auth_settings()` logs
  a once-per-process WARN when `SLM_FORGE_AUTH_ENABLED=false`. The
  flag still works (full test compatibility) but the path forward is
  `make auth ENABLED=true` + `make auth-token EMAIL=<user>` for dev
  iteration. Removal is tracked in
  `docs/specs/2026-06-29-multi-tenancy-identity.md`.

## Fixed

- **"Run agent" no longer silently fails.** `apps/web/src/pages/Agents.tsx`
  now parses the new structured 422 body into a readable inline banner
  (`"Missing or invalid: dataset, task_description — …"`) instead of
  rendering `[object Object]`. Backend / frontend agree on the shape.

## Migration

- **No env vars required for the legacy path.** Existing setups
  continue to work with `SLM_FORGE_AUTH_ENABLED=false`; you just see
  a deprecation warning on startup.
- **For the new tenanted path, set:**
  - `SLM_FORGE_AUTH_ENABLED=true`
  - `SLM_FORGE_KEYCLOAK_URL=http://keycloak:8080` (or your host)
  - `SLM_FORGE_KEYCLOAK_REALM=slm-forge`
  - `SLM_FORGE_WORKER_CLIENT_ID=slm-forge-worker`
  - `SLM_FORGE_WORKER_CLIENT_SECRET=<from realm-export.json>`
- **DB migrations** are additive and reversible. `init_db()` runs
  `_migrate_runs/sessions/exports/metrics/autofix` which `ALTER TABLE
  ADD COLUMN` for the three Phase C tenancy columns + Phase B's five
  trace nesting columns, only if absent. No backup required, but a
  copy of `data/slm_forge.db` before first boot is recommended.
- **Existing rows in Run/Session/Export/Metric/AutoFix carry
  `tenant_id=NULL`.** `scope_query` does not surface them to any user.
  Either re-create the rows you care about (and they'll get the
  caller's tenant), or use a future `make migrate-claim-legacy
  TENANT=X USER=Y` script to claim them.
- **Existing rows in `hermes_traces` backfill to `kind='skill'`** with
  NULL `trace_id`. They render in Flat view exactly as before; in Tree
  view they appear as their own root rows.
- **Re-import the Keycloak realm** if you want the new demo users +
  worker client locally:
  ```bash
  make auth-down
  make auth ENABLED=true   # re-import is automatic on first boot
  ```

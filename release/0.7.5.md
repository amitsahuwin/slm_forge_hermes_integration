# 0.7.5 — API startup never auto-resumes user work + explicit Rerun

> Format: Keep a Changelog · SemVer 0.7.4 → 0.7.5 — additive +
> behavior change in startup recovery, plus a new Rerun endpoint and
> UI button. No DB migrations. No new env vars.

The Phase R lifespan hook used to re-queue every `TrainingSession`
left in `running` on API restart, which (a) auto-restarted experiments
that had already finished (their final `status=completed` PATCH never
landed) and (b) hammered Ollama on every boot because the ratchet
worker immediately picked up the re-queued sessions and asked Hermes
for fresh mutation proposals. 0.7.5 makes startup recovery a
reconcile-or-fail operation; the user reruns explicitly.

## Added

- **`POST /api/v1/sessions/{id}/rerun`.** Clones a session's config
  (dataset, base_model, trainer_backend, method, hyperparameters,
  ratchet controls, target metric, drift threshold) into a brand-new
  `queued` `TrainingSession` named `<original> (rerun)`. The source
  row is never mutated — its history (runs, metrics, best pointer,
  error message) stays intact. The ratchet worker picks the new
  session up via its normal queue poll. Auth-guarded with
  `@requires("create", "experiment")` like `create_session`.

- **Rerun button on the Experiment detail page.** Visible when the
  experiment status is `failed`, `completed`, or `cancelled`. Click
  posts to the new endpoint and navigates to the freshly-queued
  experiment. Lives at `apps/web/src/pages/ExperimentDetail.tsx`
  alongside the existing status badge.

## Changed

- **API startup never auto-resumes user work.** See
  `docs/adr/0004-startup-recovery-never-auto-resumes.md`.
  - `TrainingSession`s with `status="running"` on boot are now
    reconciled to a terminal state instead of flipped back to
    `queued`. If any child run is `completed`, the session moves to
    `completed` (preserving any existing `best_run_id`, or deriving
    one from the lowest `final_val_loss` of the completed children).
    Otherwise the session moves to `failed` with a clear "Rerun
    manually" / "Click Rerun" message in `error_message`.
  - `Run`s touched by startup recovery
    (`release_expired_claims(include_legacy=True,
    stranded_action="fail")`) now go to `failed` instead of `queued`.
    A new `stranded_action` parameter on `release_expired_claims` lets
    the mid-operation sweep called from `claim_next_run` keep the
    existing requeue behavior — a dead worker's stale claim still goes
    back into the pool for a living worker to pick up.

## Fixed

- **Ollama no longer gets hammered on API restart.** Re-queued
  sessions used to trigger fresh Hermes mutation proposals on every
  boot; this cycle is gone.
- **Completed experiments stop showing a red "Re-queued by API
  startup recovery" banner.** The session keeps its `best_run_id`/
  `best_metric_value` and reads as `completed` in the UI.

## Migration

- No schema changes. No env vars to set.
- Existing rows that have the old "Re-queued by API startup recovery"
  `error_message` are left as-is on first boot under the new code —
  cosmetic only; self-heals as the user moves on.
- After upgrading, restarts of the API will mark genuinely-orphaned
  experiments as `failed` rather than restarting them. To resume one,
  rerun it manually (Phase 2 will ship an explicit Rerun button on
  the experiment detail page).

## Verification

```bash
# Unit/integration
uv run pytest -q tests/api/test_startup_recovery.py tests/api/test_run_claiming.py

# End-to-end
make dev-d && make trainer && make ratchet
# Start a tiny experiment with max_rounds=2; let it complete.
# Simulate the bug: sqlite3 data/slmforge.db \
#   "UPDATE sessions SET status='running' WHERE id=<id>"
docker compose restart api
# Expected: session stays/reconciles to completed (or failed with a
# Rerun message), NOT queued. `docker compose logs ratchet` should be
# quiet — no Hermes proposals fired by the restart.

# UI: open the experiment in the web app — no rose-red "Re-queued"
# banner; best run still selected if the experiment had succeeded.
```

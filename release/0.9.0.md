# 0.9.0 — Phase D: Per-user tenant isolation (clean-slate cutover) — **BREAKING**

> Format: Keep a Changelog · SemVer 0.8.0 → 0.9.0 — **breaking schema change**.
> Phase D wires per-user + per-tenant boundary enforcement through every router and ships
> a one-shot `make wipe-clean` to start from a fresh DB. All lab history pre-dating Phase D
> is destroyed on upgrade — by explicit design choice, no migration shim.
>
> Spec: `docs/specs/2026-06-30-phase-d-user-isolation.md` · ADR: `docs/adr/0007-per-user-isolation-cutover.md`

---

## ⚠ Breaking

- **`make wipe-clean` is required once on upgrade.** It deletes every row in `runs`, `training_sessions`, `exports`, `metrics`, `hermes_traces`, `auto_fix_attempt`, `chat_conversations`, `chat_messages`, `heartbeat`; removes `/app/runs`, `/app/exports`, `/app/storage`, `data/datasets/users/`; deletes and recreates every `slm-forge-*` Ozone bucket; then re-seeds the bundled sample datasets to `data/datasets/global/`. Run with `SLM_FORGE_WIPE_CONFIRM=YES make wipe-clean`. The command refuses without that env var.
- **Dataset filesystem layout changed.** Bundled samples now live at `data/datasets/global/<name>/` (was `data/datasets/<name>/`). User uploads now land at `data/datasets/users/{tenant_id}/{user_id}/<name>/`. Any external script that walked `data/datasets/` directly needs updating.
- **`HermesTrace` adds a `user_id` column.** Pre-Phase-D trace rows are removed by `wipe-clean` rather than backfilled.

## Added

### Enforcement
- Every list/get/patch/delete endpoint on `runs`, `sessions`, `exports`, `metrics`, and `traces` now wraps its query in `scope_query()`. Non-admin users see only their own rows; admin role sees every row in their own tenant; nobody sees cross-tenant.
- Every create endpoint on those routers stamps `tenant_id` + `user_id` from the JWT-derived `Identity`. Client-supplied values for those fields are ignored.
- `*Patch` Pydantic models reject `tenant_id`/`user_id` mutation attempts with HTTP 422.

### Datasets
- Per-user upload isolation: `POST /api/v1/datasets/...` writes to `data/datasets/users/{tenant_id}/{user_id}/<name>/`.
- Bundled samples (`make seed-data` output) live under `data/datasets/global/` and are visible to every authenticated user, read-only.
- `apps/api/services/datasets_paths.py` — new helper module: `user_dataset_root(identity)`, `visible_dataset_dirs(identity)`.
- Path-traversal rejection on dataset names (`..`, `/`, leading `.`) → 400.

### Tooling
- `scripts/wipe_clean.py` — env-guarded clean-slate script, structured JSON logging per op.
- `make wipe-clean` Makefile target (with help text).
- AST-walk contract test (`tests/api/test_router_scoping_invariant.py`) — flags any new `select(Model)` in `apps/api/routers/` without an adjacent `scope_query`. Escape hatch documented for legitimate exceptions.

## Changed

- `HermesTrace` now has a `user_id` column (`index=True`, default `"default"`). Worker-side trace writes derive both `tenant_id` and `user_id` from the parent `Run` row.
- Worker artifact uploads (`packages/trainer/runner.py`, `packages/exporter/pipeline.py`, ratchet's run-creation path) read `Run.tenant_id` and `Run.user_id` off the claimed Run row when assembling Ozone object keys. (Previously: may have used worker identity.)
- `scripts/seed_datasets.py` writes to `data/datasets/global/`.

## Unchanged

- Public API route surface — every existing route stays at the same path with the same shape; the only observable change is what rows it returns to each caller.
- Worker claim path — workers still claim runs from any tenant (system-level by design); the boundary enforcement is on the API side, not the claim queue.
- Object storage isolation — `slm-forge-{tenant_id}` Ozone buckets continue to provide a second wall.
- `auth ENABLED=false` mode — synthetic admin still sees the `local` tenant; dev loop unchanged.

## Migration / verification

```bash
# 1) Pull the release, wipe state, restart auth.
git pull
make auth-down
SLM_FORGE_WIPE_CONFIRM=YES make wipe-clean
make auth ENABLED=true

# 2) UI smoke (two browsers — log fully out of any existing session first).
#    Sign in as alice@acme. Create a run. Switch to bob@acme — empty list.
#    Switch to admin@acme — sees Alice's run.
#    Switch to carol@globex — empty list (different tenant, even though admin).

# 3) curl probe.
TOKEN_ALICE=$(make auth-token EMAIL=alice@acme PASSWORD=alice1234 | tail -1)
TOKEN_BOB=$(make auth-token EMAIL=bob@acme PASSWORD=bob12345 | tail -1)
RUN_ID=$(curl -s -X POST http://localhost:8000/api/v1/runs \
  -H "Authorization: Bearer $TOKEN_ALICE" -H "Content-Type: application/json" \
  -d '{"name":"alice-run","base_model":"qwen2.5-3b","trainer_backend":"mlx","dataset_path":"global/example/train.jsonl"}' \
  | jq -r .id)

# Bob attempts to read it → expect 404.
curl -s -o /dev/null -w "%{http_code}\n" \
  -H "Authorization: Bearer $TOKEN_BOB" \
  http://localhost:8000/api/v1/runs/$RUN_ID
# expected: 404

# Alice can read her own → expect 200.
curl -s -o /dev/null -w "%{http_code}\n" \
  -H "Authorization: Bearer $TOKEN_ALICE" \
  http://localhost:8000/api/v1/runs/$RUN_ID
# expected: 200
```

# 0.11.0 — Dynamic model registry (Models tab)

Format: Keep a Changelog · SemVer. 0.10.0 → 0.11.0 is additive, **non-breaking**.

The model catalog is no longer hardcoded. A new **Models** tab lets you browse
the effective catalog and register any HuggingFace model by pasting its repo id.
Registration runs as a background job (Jobs tab, `modeldownload:<id>`) that
validates the repo via the HF Hub API and persists a global catalog entry.
Registered models then appear everywhere — New Run and New Experiment dropdowns —
with no hardcoding. Weights are still fetched by the trainer worker at train
time, so the training path is untouched.

## Added

### Models tab

- **`POST /api/v1/models/download`** — queues a register+validate job; returns
  `202 {job_id:"modeldownload:<id>", hf_id, target_backend, status}`. Admin-only.
  Validates `hf_id` (`org/name` charset) → 422; backend ∈ {mlx,cuda} → 422.
- **`GET /api/v1/models/registry`** — user-registered rows (manage/delete list);
  readable by any authenticated user.
- **`DELETE /api/v1/models/registry/{key}`** — remove a registered model
  (`204`; `404` if absent). Admin-only.
- **`GET /api/v1/models/v2`** now returns `effective_catalog()` = built-in seeds
  + registered rows, so registered models appear in both creation dropdowns.
- New **Models** page (`apps/web/src/pages/Models.tsx`), nav tab, route, API
  client, and Products-page entry. Backend auto-detect (MLX/CUDA) with override.

### Background job runner

- `apps/api/services/model_download_jobs.py` drives
  `queued → processing → succeeded|failed`, never raises. Metadata via
  `HfApi().model_info` (uses `HF_TOKEN` for gated repos), bounded retry with
  backoff+jitter on transient errors; terminal, clearly-messaged failures for
  missing / gated-without-token repos (no silent fallback). On success it upserts
  a global `RegisteredModel` (unique by `model_id`).

### Jobs aggregator

- New `modeldownload` kind + `_resolve_model_download` resolver
  (tenant-scoped via `scope_query`; cross-tenant → 404). Progress surfaces
  detected `{hf_id, backend, family, params, arch, gated, registered_key}`;
  deep link `/runs/new` once succeeded else `/models`. Jobs tab live-polls the
  in-flight job.

### Data model

- `model_download_jobs` (`ModelDownloadJob`, tenant-scoped) and
  `registered_models` (`RegisteredModel`, global) tables, auto-created via
  `create_all`. Startup reconciler drives orphaned `queued`/`processing`
  download jobs → `failed`.

### Authz

- New OPA `model` resource in `policies/role_matrix.rego`: admin `create`/
  `delete`; read open to authenticated users. Client `permissions.ts` mirrors it
  (cosmetic; OPA is the source of truth).

## Changed

- `list_models_v2`, `find_by_model_id`, `allowed_model_ids`, `get_model_by_key`,
  `default_model_id`, and `validate_run_request` now read through
  `effective_catalog()` — dynamic for registered models. Public signatures and
  built-in seeds unchanged.
- `_legacy_view` (`GET /api/v1/models`) guards `.get("mlx")` so cuda-only
  registered models don't break the legacy flat shape.
- **`grad_checkpoint` now defaults to `true`** for new Runs and Experiments
  (Run model, `RunCreate`, `TrainingSession`, `SessionCreate`, ratchet child-run
  payload). Root cause of run #26's Metal OOM: activation memory scales with
  seq², so one long-row dataset (max 2,503 tokens vs 166 in the samples) blew
  past the working-set limit at `batch_size=4 × seq 2048` — verified fix takes
  the same run from >27 GB OOM to a 7.9 GB peak (~25% slower per iter). New
  Run / New Experiment expose a **Gradient checkpointing** toggle to opt out.
- Sessions gain a `grad_checkpoint` column (additive migration, default `1`);
  the ratchet loop threads it onto every child run (legacy rows → `true`).

## Migration / impact

- Additive only. New tables are created automatically; no data migration.
- Existing UI/API clients that omit `grad_checkpoint` now get it **on** — retry
  memory-limited runs as-is; pass `"grad_checkpoint": false` for old behavior.
- No new config. `HF_TOKEN` (existing) is used only to read gated/private repos
  and is never logged.
- Training path unchanged — weights are fetched by the worker at train time.

## Verify

```bash
# UI: Models → paste Qwen/Qwen2.5-1.5B-Instruct → Download → lands on
#     /jobs?id=modeldownload:<id>, polls to succeeded → appears in New Run.

# curl (auth on):
API=http://localhost:8000
TOKEN=$(make auth-token)
curl -s -X POST "$API/api/v1/models/download" \
  -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
  -d '{"hf_id":"Qwen/Qwen2.5-1.5B-Instruct"}'
# → {"job_id":"modeldownload:1","hf_id":"Qwen/Qwen2.5-1.5B-Instruct",...}
curl -s "$API/api/v1/jobs/modeldownload:1" -H "Authorization: Bearer $TOKEN"
curl -s "$API/api/v1/models/v2"           -H "Authorization: Bearer $TOKEN"
```

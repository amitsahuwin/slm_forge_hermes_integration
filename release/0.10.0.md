# 0.10.0 — Large dataset uploads via background ingest jobs

> Format: Keep a Changelog · SemVer 0.9.0 → 0.10.0 — additive, **non-breaking**.
> Dataset file uploads are no longer capped at 10 MB. Files above the sync
> threshold stream to object storage and are parsed + split in a constant-RAM
> background job, tracked in the Jobs tab as `ingest:<id>`.
>
> Spec: `docs/specs/2026-07-14-large-dataset-upload.md` ·
> Plan: `docs/plans/2026-07-14-large-dataset-upload.md`

---

## Added

### Upload path
- **`POST /api/v1/ingest/file/large`** — streams an upload to object storage
  (never buffered in RAM), inserts a `queued` `IngestJob`, schedules an
  in-process async parse/split, and returns `202` with
  `{job_id: "ingest:<id>", name, status, detected_format, raw_bytes}`.
- Files at or below `SLM_FORGE_INGEST_SYNC_MAX_BYTES` (10 MB) keep the existing
  synchronous path with live preview + optional Ollama conversion. The New
  Dataset → File form auto-routes by `file.size`.
- Hard upload cap `SLM_FORGE_MAX_UPLOAD_BYTES` (500 MB default), enforced
  mid-stream: a breach aborts the transfer, deletes the partial object, and
  returns `413`. Duplicate dataset name → `409`; non-JSONL/CSV → `422`;
  invalid name → `400`.

### Background job runner
- `apps/api/services/ingest_jobs.py::_run_ingest_job` — loads the raw object,
  parses via constant-RAM streaming primitives
  (`packages/dataset_ingest/streaming.py`: `iter_jsonl_records`,
  `iter_csv_records`, `StreamingSplitWriter`), writes to a per-user staging
  dir, then atomically renames into the published dataset dir. On failure the
  staging dir is removed, the row is marked `failed`, and the raw object is
  kept for diagnosis.
- `IngestJob` table (`apps/api/models/ingest_job.py`) with tenant/user scoping,
  status enum, counts, and byte tallies. Registered in `init_db()`.

### Jobs tab
- New `ingest` kind in the federated Jobs aggregator
  (`apps/api/routers/jobs.py`): tenant-scoped lookup (cross-tenant → 404),
  progress (`raw_bytes`, `records_total`, `train`/`valid`/`canary`/`dropped`,
  `format`), and a deep link to `/datasets/<name>` once succeeded.
- Frontend (`apps/web/src/pages/Jobs.tsx`): `ingest` kind + `processing`
  status style, an example id, and 2-second silent live-polling while a job is
  `queued`/`processing`.

### Reliability
- **Restart reconciler** (`_reconcile_orphaned_ingest_jobs`, wired into
  `init_db()`): in-process ingest tasks are lost on an API restart, so any
  `queued`/`processing` row is driven to `failed` with
  `error_message="interrupted by API restart"` at startup. Terminal rows are
  never touched.

## Config

| Env var | Default | Purpose |
| --- | --- | --- |
| `SLM_FORGE_MAX_UPLOAD_BYTES` | `524288000` (500 MB) | Hard cap on any dataset upload. |
| `SLM_FORGE_INGEST_SYNC_MAX_BYTES` | `10485760` (10 MB) | Sync/async routing threshold. Validated `<= MAX_UPLOAD_BYTES` at startup (fail-fast). |

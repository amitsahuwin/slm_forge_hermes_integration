# 0.7.4 — Auto-fix: PR pipeline + LiteLLM proxy + diagnostic crash endpoint

> Format: Keep a Changelog · SemVer 0.7.3 → 0.7.4 — additive only.
> No DB migrations. One new env var (`AUTOFIX_MODEL`), one new
> `AUTOFIX_DEPLOY` value (`pr`), and one new opt-in docker-compose
> profile (`autofix`).

The self-healing error reporter shipped in 0.7.0 captured exceptions but
the dev-mode loop only committed to a local sandbox branch — no PR ever
opened, no remote artifact. 0.7.4 closes that gap and routes the SDK's
codegen through a LiteLLM proxy so the auto-fix model can be a local
Ollama model (`qwen3:30b-a3b`) rather than the Anthropic Cloud.

## Added

- **`AUTOFIX_DEPLOY=pr` deploy mode** (was a no-op before; now wired).
  After a verified fix lands on the sandbox branch, the orchestrator
  pushes `auto-fix/<fp12>-<utcstamp>` to `origin` and opens a PR via
  the GitHub REST API. `AutoFixAttempt.pr_url` is populated; the
  `/autofix` admin tab surfaces the URL alongside the diff. Push or
  PR-API failure marks the attempt `failed` with a structured reason
  — the row never silently disappears.

- **LiteLLM proxy as an opt-in docker-compose service.**
  `make litellm-up` starts a `litellm-proxy` container on `:4000` that
  speaks the Anthropic Messages API on the front and translates to
  Ollama on the back. `claude_agent_sdk` posts here instead of
  `api.anthropic.com`, hitting host Ollama's `qwen3:30b-a3b` through
  the alias defined in `litellm/config.yaml`. Profile-gated so
  default `make dev` still skips the proxy. See `docs/adr/0003-litellm-for-autofix-sdk.md`.

- **`AUTOFIX_MODEL` env var** forwarded into
  `ClaudeAgentOptions(model=...)`. Defaults to
  `anthropic/claude-3-5-sonnet-20241022` (the LiteLLM alias). Swap to
  `anthropic/qwen3-30b-a3b` to make the qwen route obvious in proxy
  logs, or to a real Anthropic model name for cloud deployments.

- **`POST /api/v1/admin/__debug__/raise`** (dev-only, admin-only).
  Operator handle for verifying the capture pipeline end-to-end. Body:
  `{"exc_type": "ValueError", "message": "test"}`. Returns 500 with the
  redacted traceback in development mode; 404 in production. The raise
  site lives in `apps/api/services/_debug_target.py`, which carries a
  `# NO_AUTOFIX` marker so the SDK doesn't waste a sandbox commit on
  the intentional crash.

- **Source-level contract tests** for the worker exception hooks
  (`tests/error_responder/test_worker_hooks.py`). Catches accidental
  removal of the `try → report_exception_sync → flush → raise` wrapper
  in trainer/ratchet/exporter `__main__.py`.

## Changed

- `AutoFixOutcome` gained a `pr_url: str | None` field. Returned at
  the existing call sites; no consumer changes required.

- `_update_attempt(pr_url=…)` plumbing — persists the PR URL on the
  `AutoFixAttempt` row. SQLite schema is unchanged (`pr_url` was
  already in the model since 0.7.0; this just wires it).

- `.env.example` reorganized around the auto-fix flow with explicit
  setup recipes for (A) LiteLLM-proxied local Ollama and (B) real
  Anthropic Cloud. Documents the required GITHUB PAT scopes
  (Contents: write, Pull requests: write, Issues: write).

## Fixed

- **Diagnosis** (no code fix in this release, just clear docs):
  `GITHUB_REPO` MUST be `owner/repo`. The `.env` example previously
  showed only the repo name in some setups, which 404'd every GitHub
  API call. `.env.example` now spells this out; the user's local
  `.env` carries a `TODO: prefix with "owner/"` comment.

## Migration

No DB migration. To enable the new flow on an existing checkout:

```bash
# 1. Add to .env (.env.example carries the full template):
AUTOFIX_DEPLOY=pr
AUTOFIX_MODEL=anthropic/claude-3-5-sonnet-20241022
ANTHROPIC_BASE_URL=http://localhost:4000
ANTHROPIC_API_KEY=sk-local-litellm-master
LITELLM_MASTER_KEY=sk-local-litellm-master
GITHUB_REPO=<owner>/<repo>        # ← must include the owner prefix
GITHUB_TOKEN=<fine-grained PAT>   # Contents/PRs/Issues write scope

# 2. Pull the qwen model + start the proxy:
ollama pull qwen3:30b-a3b
make litellm-up

# 3. Restart the API so it picks up the new env:
make dev

# 4. Verify with the diagnostic endpoint:
TOKEN=$(make auth-token)
curl -X POST -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"exc_type":"ValueError","message":"e2e test"}' \
  http://localhost:8000/api/v1/admin/__debug__/raise
#    → 500 (expected); within ~3 min the /autofix tab shows the row.
```

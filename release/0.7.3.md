# 0.7.3 — Chat tab fix-pack

> Format: Keep a Changelog · SemVer 0.7.2 → 0.7.3 — four bug fixes, no
> contract changes, no migrations.

Four bugs reported on the Chat tab that surfaced together once
auth-on chat became real. One was a regression from 0.7.2's
history-replay work; the other three were pre-existing gaps that the
new persistence + auth made visible.

## Fixed

- **Chat reload was unformatted (regression from 0.7.2).**
  After 0.7.2's history-replay changes, `_persist_turn` split tool
  calls + results into discrete rows. The React Chat tab still
  expected the legacy single-assistant-row shape with
  `tool_calls_json` = list of results; on reload it had nothing to
  render as a ToolCard and dropped the JSON into plain text. The
  visible symptom: closing and reopening the chat showed *"all the
  responses are in plain text not in format"* and Qwen3's
  `</think>` tags leaking through.
  Fix: revert `_persist_turn` to write a single assistant row
  carrying the results list (matching the live-stream shape the
  UI consumes), and teach `_load_history_as_langchain` to detect
  that legacy shape and synthesise the AIMessage(tool_calls=…) +
  ToolMessage pair the agent expects on the next turn. Both shapes
  read-compatible going forward.

- **Chat tab scroll-with-page (panels not pinned).**
  The grid was sized `h-[calc(100vh-12rem)]` but the real chrome
  height is ~9rem, so the chat container overflowed the viewport
  and the whole page scrolled — dragging the left (conversations)
  and right (templates) asides along. Fix: switch to
  `h-[calc(100dvh-9rem)]` with `overflow-hidden` on the grid and
  `min-h-0` on each flex child so internal scrollers actually
  clip. Only the middle thread scrolls now; left + right panels
  stay pinned with their own internal scroll when long.

- **Cannot edit hyperparameters before starting an experiment.**
  `StartExperimentCard` had a non-functional "Edit" button — the
  values were read-only and clicking Start always submitted the
  agent's original suggestion. Fix: edit mode now reveals per-field
  inputs (typed inputs for numerics, text for strings); the form
  state is the payload that gets POSTed to `/api/v1/sessions`. A
  Reset button restores the agent's original values; an "edited"
  badge confirms the working copy diverges.

- **Synthesised dataset never persisted; experiments then failed.**
  Root cause: the LangChain `synthesize_dataset` tool was **never
  registered** in `ALL_TOOLS`. When a user asked the chat to
  synthesise, the LLM had no tool to call, so it hallucinated a
  success response — the dataset never landed on disk, and any
  subsequent `start_experiment` against that name 404'd.
  Fix: add `synthesize_dataset(source_dataset, new_dataset,
  target_count, style_guidance)` that POSTs to
  `/api/v1/synth/start` and returns the `job_id` + a next-step
  hint, plus `get_synth_job_status(job_id)` to poll. Both
  registered in `ALL_TOOLS`. Bounded `target_count` to [8, 5000]
  (matches the API's own validation) so obviously-bad values fail
  early.

## Added

- `synthesize_dataset` and `get_synth_job_status` tools in
  `packages/chat_agent/tools.py` (registered in `ALL_TOOLS`).

## Verification

```bash
uv run pytest -q tests/chat_agent/
cd apps/web && npm run build
```

Manual click-through:

1. **Bug #1 scroll:** Open Chat with a long conversation. Scroll the
   middle column — the left "conversations" list and right
   "templates" panel stay pinned. Try scrolling those panels; they
   scroll independently.
2. **Bug #2 synth:** Ask the chat "synthesise 200 records from
   medical-qa-rural-tn into medical-qa-expanded". The chat now
   actually fires the synth job, returns the job_id, and follows
   up with `get_synth_job_status` calls. After completion, the new
   dataset appears in the Datasets tab and `start_experiment` can
   reference it.
3. **Bug #3 hp edit:** Trigger a `start_experiment` card from chat.
   Click **Edit**, change `iters`, hit **Start** — the new value
   shows up on the resulting Session row.
4. **Bug #4 reload format:** Have a chat conversation that fired
   tools (e.g. "list runs"). Close the Chat tab, reopen it, click
   the conversation in the list. Tool results render as ToolCards
   (the formatted green cards), not as plain JSON text. The
   `</think>` tags no longer appear.

## Notes / non-goals

- The Qwen3 `<think>...</think>` reasoning tags are still passed
  through verbatim in raw `content`. They render correctly inside
  ToolCards (because the JSON is structured), but stray
  `</think>` text from agent prose isn't stripped. Stripping
  needs to happen at the agent prose level — separate spec.
- No schema migration; no env-var changes.

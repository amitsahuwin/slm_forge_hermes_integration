# 0.7.0 — Hermes Hardening + Self-Healing Error Reporter

> Format: Keep a Changelog (https://keepachangelog.com/). Semver bump:
> 0.6.0 → 0.7.0 — additive features + one user-facing contract change
> (HTTPException detail shape on catalog-rejected runs and synth 4xx).

This release lands the entire **Hermes Hardening Ultraplan**:
Workstream 1 (PR-1 → PR-4) cleans the Hermes/Ollama bridge of four
CLAUDE.md rule violations and wires three previously-orphan skills into
production paths; Workstream 2 (PR-A → PR-C) introduces a self-healing
error reporter that opens deduplicated GitHub issues in production and
drives Claude Agent SDK auto-fixes in development; Workstream 3 ships a
client-facing product guide + a polished `/product` showcase tab in the
UI.

## Added

- **Auto post-mortem on run failure (PR-2).** When a run transitions to
  `status=failed`, the API enqueues a `BackgroundTask` that calls the
  existing `failure_post_mortem` Hermes skill and stores the resulting
  Markdown on the run row + a sidecar `runs/<id>/post_mortem.md`.
  Polled at `GET /api/v1/runs/{run_id}/post_mortem`.
- **Plain-English error remedy on 4xx (PR-3).** Catalog-rejected runs
  (422) and synth-router 4xx paths now carry a Hermes-generated remedy
  in `detail.remedy` (4-second wall cap; falls back to `null` on
  timeout). New skill: `.hermes-skills/error_remedy.md`.
- **Dataset QA on ingest preview (PR-4).** Every
  `/api/v1/ingest/*/preview` returns a `qa_id`; a background task runs
  the `data_quality_review` skill on the first 50 rows and the UI
  polls `GET /api/v1/ingest/qa/{qa_id}` for warnings (duplicates,
  PII, off-topic, format mismatches).
- **Self-healing error reporter (PR-A + PR-B).** New package
  `packages/error_responder/` captures every uncaught exception across
  the API + workers, fingerprints + redacts it, and:
  - **Production:** opens or comments on a deduplicated GitHub issue
    (no PyGithub; native `httpx`). Storm protection: ≥10 in 60s
    suppress further posts until the window rolls.
  - **Development with `AUTOFIX_ENABLED=true`:** drives
    `claude_agent_sdk` through a sandbox-branch loop with ten preflight
    gates, a non-negotiable test-quality gate (rerun against pre-fix
    code via `git stash`; must FAIL before, PASS after), full pytest
    suite under a 120s wall cap, then auto-commits on
    `auto-fix/<fp12>-<utcstamp>`. **Main is never touched.**
- **Auto-Fixes admin tab (PR-C).** New React page at `/autofix`
  (admin-only). Stats panel + filterable list + detail drawer with
  captured diff, correlation IDs, abandon button.
- **Product showcase tab (Workstream 3).** New React page at
  `/product` visible to all users. Polished landing/about page
  mirroring `docs/SLM_FORGE_PRODUCT_GUIDE.md` section-for-section
  (hero, 11 tab cards, microservices grid, Hermes integration table,
  skills catalog, demo checklist).
- **Client product guide.** New `docs/SLM_FORGE_PRODUCT_GUIDE.md` —
  one self-contained Markdown covering every screen, every microservice,
  and every Hermes touchpoint in plain English.

## Changed

- **Hermes bridge hardening (PR-1).**
  - `_call_ollama` now retries on transient failures with exponential
    backoff + jitter via `tenacity`. Retries: `ConnectError`,
    `ReadTimeout`, `RemoteProtocolError`, 429/502/503/504. Default 3
    attempts; tunable via `HERMES_MAX_RETRIES`.
  - `propose_mutation` no longer fabricates a silent
    "LR halving" fallback on JSON / Pydantic parse failure — raises
    `MutationProposalError`. `loop.run_session` records the failure as
    an iteration skip and aborts the session after
    `HERMES_MAX_PROPOSAL_FAILURES=3` consecutive failures.
  - Raw response bodies are no longer logged. `HermesTrace` rows for
    PII-risky sources (`skill:dataset_synth`, `skill:ingest_dataset`,
    `skill:auto_label_unlabeled`, `skill:data_quality_review`) are
    redacted by default; override via `HERMES_TRACE_REDACT_SOURCES`.
  - Every `HermesTrace` row now carries a `tenant_id` (default
    `"default"`). Workers resolve via `SLM_FORGE_TENANT_ID` /
    `SLM_FORGE_DEFAULT_TENANT`; the API resolves via the
    `RequestContextMiddleware` contextvar (`X-Tenant-Id` header
    accepted).
- **HTTPException detail shape (PR-3).** For catalog-rejected
  `POST /api/v1/runs` and 4xx paths in `POST /api/v1/synth/start`, the
  `detail` field is now an object: `{"message": str, "remedy": str | null}`.
  Plain-string detail is preserved everywhere else. The UI adapter at
  `apps/web/src/lib/api.ts:extractDetailMessage` falls back gracefully
  for both shapes.

## Security

- **Secret redaction on every captured error (PR-A).** Six conservative
  patterns (Bearer, `api_key=` / `password=` / `token=` / `secret=`,
  AKIA*, `sk-(ant|live|proj)-*`, JWT, email) run BEFORE traceback text
  enters either the SDK prompt or the GitHub issue body. Idempotent;
  test suite asserts via sentinel tokens.
- **Tenant-aware trace audit (PR-1 A4).** Every Hermes call now records
  a `tenant_id` for future multi-tenant enforcement. Single-tenant
  deployments keep `"default"` and need no change.

## Migration

### Required

- **None for production deployments.** All schema changes are additive
  forward-only migrations that run on the next `init_db()` (i.e. the
  next API restart). Default values back-fill existing rows safely.
- **DEPLOYMENT_MODE in production** must set `GITHUB_TOKEN`. Without it,
  the error responder records the captured error locally as
  `status=skipped` but doesn't post to GitHub. The API will refuse to
  start if `DEPLOYMENT_MODE=production` and `GITHUB_TOKEN` is unset
  (CLAUDE.md rule 23: fail-fast on missing required config).

### Optional

- **Enable dev-mode auto-fix.** Install the optional extra and set the
  env switches:
  ```bash
  uv sync --extra error-responder
  export DEPLOYMENT_MODE=development
  export AUTOFIX_ENABLED=true
  export ANTHROPIC_API_KEY=...  # or ANTHROPIC_AUTH_TOKEN
  ```
  The auto-fix loop refuses to run on `main`, on a dirty tree, against
  files in the denylist, or against files marked `# NO_AUTOFIX`.
- **Tune the new behaviours.** Every new feature has a kill switch:
  `HERMES_POST_MORTEM_ENABLED`, `HERMES_REMEDY_ENABLED`,
  `HERMES_QA_ENABLED`, `ERROR_REPORTER_ENABLED`, `AUTOFIX_ENABLED`.

### Schema (additive — no manual ALTERs needed)

- `hermes_traces`: `+ attempts INTEGER DEFAULT 1`,
  `+ tenant_id TEXT DEFAULT 'default'`.
- `runs`: `+ post_mortem TEXT`, `+ post_mortem_status TEXT DEFAULT 'skipped'`,
  `+ post_mortem_input_hash TEXT`, `+ post_mortem_generated_at TIMESTAMP`.
- `auto_fix_attempt`: **new table** (created by `SQLModel.create_all`).

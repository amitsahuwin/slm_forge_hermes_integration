# 0.9.1 — Ingest-time CSV cleaning + chat-format conversion

> Format: Keep a Changelog · SemVer 0.9.0 → 0.9.1.
> Root-caused from run 33's gibberish adapter: the `sx-100rows` CSV was
> ingested via the `{"text"}` column-dump fallback with zero content
> validation, so corrupted rows (misaligned multi-line cells, Python-list
> reprs) were trained on verbatim. This release makes every CSV ingest
> mapped-or-fail, cleaned, and published as chat records.
>
> Spec: `docs/specs/PHASE_INGEST_CSV_CHAT_SPEC.md`

---

## Added

- **`packages/dataset_ingest/csv_chat.py`** — shared CSV → chat cleaning core
  used by both the sync and streaming ingest paths:
  - `resolve_mapping(header, samples)` — tiered column mapping: normalized
    header-hint heuristics (issue/question/prompt/… → user;
    fix/answer/completion/… → assistant) first, then the new
    `csv_column_mapping` Hermes skill (qwen3 via Ollama) for ambiguous
    schemas. Unresolvable or Hermes-down → `MappingError` with
    "start Ollama or rename the columns to prompt/completion".
  - `RowCleaner` — per-row drop rules with per-reason counters: empty /
    <3-char fields, Python-list reprs (`['TRUE', 'P4', …]`), control
    characters, exact duplicates (sha256 16-byte digests).
  - `CleanStats.check_threshold()` — ingest **fails (400 / failed job) when
    >50% of rows are unusable** (`DropThresholdError`).
- **`.hermes-skills/csv_column_mapping.md`** — strict-JSON skill: header +
  sample rows in, `{"prompt_column", "completion_column"}` out.
- **Preview API** (`/api/v1/ingest/preview` + URL/scrape/S3 previews) now
  returns `column_mapping`, `dropped_rows`, `drop_reasons`; the New Dataset
  page renders the resolved mapping and drop stats before you save.
- Dataset `README.md` (sync and background ingest) records the column
  mapping and per-reason drop counts.

## Changed

- **CSV is mapped-or-fail on every ingest path.** The sync `_convert`
  pipeline, `/preview`, `/from-url`, scrape, S3, and the large-file
  background job (`iter_csv_chat_records`, constant-RAM: ≤50-row mapping
  buffer + dedupe digests) all publish chat `{"messages": [...]}` records
  only. CSV no longer falls back to Ollama auto-conversion on low record
  counts.

## Removed

- The CSV `{"text"}` column-dump fallback (`csv_row_to_mlx`,
  `resolve_csv_mapping`, `parse_known("csv")`) — the source of run 33's
  untrainable dataset. `converter.csv_to_chat()` replaces it.

## Impact & migration

- Re-ingest any dataset originally imported from CSV before 0.9.1 —
  previously published `{"text"}` dumps stay on disk but should not be
  trained on. Upload the original CSV again; the cleaned chat dataset is
  written under the same flow (pick a new name; existing names are
  rejected).
- Ambiguous CSV schemas now require Ollama running (`make dev` prereq) or
  columns named `prompt`/`completion`; otherwise ingest fails with a 400
  explaining exactly that.

## Verify

- UI: New Dataset → File → pick a CSV → preview shows
  "CSV mapped to chat: `<col>` → user, `<col>` → assistant (heuristic)"
  plus dropped-row counts → Save → dataset `train.jsonl` rows are all
  `{"messages": [...]}`.
- API:
  ```bash
  curl -s -X POST http://localhost:8000/api/v1/ingest/preview \
    -F "file=@your.csv" | jq '.column_mapping, .dropped_rows, .drop_reasons'
  ```
- Negative: a garbage-majority CSV returns
  `400 … are unusable … refusing to publish`.
